## 2. 已识别的汇总边界情况

当前 `run_complete.py` 在末尾取 `r.get('test', {}).get('status')`。对于记录中明确存在 `"test": null` 的失败单元，这会触发 `AttributeError`，导致循环跑完但没有生成 `summary.json`／`DONE`。

管理员排查结束退出原因时须检查这一项。修复应使用 `(r.get('test') or {}).get('status')`，并对正常、`test:null`、缺少 test、失败、空分组这些输入做汇总验证。不得为了生成 DONE 而跳过失败数或人工写一个成功标记。当前交接仅记录该待办，没有修改正在运行的程序。

## 3. 续跑的重要语义

目前驱动只要发现单元目录下存在 `result.json` 就跳过，**失败单元也会被跳过**。因此重新执行启动脚本不等于重试失败单元。

重试前必须：

1. 确认主进程已经退出，或由负责管理员在记录理由后受控停止。不能一边训练一边移动目录。
2. 记录并保存当前配置、代码校验文件、日志和失败清单。
3. 将待重试的**整个单元目录**移到正式根目录之外，例如 `results/gen_eval/retry_archive/日期时间/任务/退化/方法/seedN/`，保留原文件。不仅删除 `result.json`：旧 trace 和模型半成品也可能影响下一次运行。
4. 进程中断留下、没有 `result.json` 的半成品单元同样先归档，再重跑。
5. 成功单元保持原样。恢复 API 服务或同配置资源后，按 ats 文档启动一次，驱动将跳过已存在的完整记录。
6. 如有旧 `DONE`／`summary.json`，在重跑前将其归档，避免把旧完成标记误认成本轮完成。不要直接覆盖失败证据。

若修复涉及模型、评分、数据切分、动作空间、预算或其他实验协议，应使用新版本结果目录，并同步修改驱动与状态脚本中的目录常量；不要把不同协议结果混进 `v2_ark_20261107`。仅修复汇总代码时，可以在保留原记录后重新计算汇总，并明确标注这是报告修复。

启动脚本会重写运行根目录的配置和代码哈希快照，因此**续跑前必须先核对并备份旧快照**，不能启动后再把新快照当作所有历史单元的来源。
